# Content schema

Source of truth for Lorito's study content. One file per card; the pipeline in
`tools/` validates these and compiles them into the app bundle.

## Layout

```
content/
  themes.json          # per-level theme registry (generated by the pipeline)
  A1/ A2/ B1/ B2/ C1/ C2/
    <id>.md            # one card per file, e.g. A1-15.md
```

A card file lives under the directory matching its `level`.

## Card file format

YAML frontmatter followed by a Markdown body:

```markdown
---
id: A1-15
level: A1
theme: a1-3
order: 15
title: "Глагол ser"
aliases: ["Verbo ser", "быть (ser)"]
related: ["A1-16", "A1-14"]
tags: ["gramática"]
---
> **Суть**
> ...Markdown body...
```

### Frontmatter fields

| Field | Required | Type | Rules |
|-------|----------|------|-------|
| `id` | yes | string | Matches `^[A-C][12]-\d{2}$` (e.g. `A1-07`). Unique across all cards. |
| `level` | yes | string | One of `A1 A2 B1 B2 C1 C2`. Must match the file's directory. |
| `theme` | yes | string | A theme id present in `themes.json` whose level equals this card's level. |
| `order` | yes | int | ≥ 1, unique within the level. Equals the numeric part of `id`. |
| `title` | yes | string | Non-empty. |
| `aliases` | no | string[] | Alternative names (Spanish term, Russian name). |
| `related` | no | string[] | Card ids; each MUST resolve to an existing card. |
| `tags` | no | string[] | Category tags: `gramática`, `vocabulario`, `ortografía`, `fonética`. |
| `recall` | no | string | Recall prompt shown on the card's front before the answer. One line, double-quoted, ≤ 200 chars, Markdown; Spanish in `*…*` (e.g. `recall: "**¿el или la?** *problema, mano, canción, agua*"`). Without it the app shows a generic prompt built from the title. |

## Levels

Six ordered levels: `A1 < A2 < B1 < B2 < C1 < C2`. Selecting a target level
includes that level and all lower levels.

## Themes

Each level is divided into ordered **themes** (sections). A theme groups a
**contiguous** run of cards by `order` — themes never interleave. The registry
`themes.json` declares every theme:

```json
{ "themes": [ { "id": "a1-1", "level": "A1", "title": "Орфография и фонетика", "order": 1 } ] }
```

Theme ids are `<level-lowercased>-<n>` (e.g. `a1-1`). Titles come from the
source level MOC section headings.

## Body conventions

The Markdown body uses callout blockquotes for the four standard sections,
rendered specially by the app:

- `> **Суть**` — essence / summary
- `> **Ключевые моменты**` — key points
- `> **Частые ошибки**` — common mistakes
- `> **Полезно**` — useful notes

Tables (GFM) are supported. The card `title` is stored in frontmatter, so the
body SHOULD NOT repeat it as a top-level `#` heading.

## Practice exercises

Practical exercises live alongside cards, one file per exercise:

```
content/
  A1/ A2/ B1/ B2/ C1/ C2/
    exercises/
      <id>.md            # one exercise per file, e.g. A1-EX-01.md
```

An exercise file is YAML-ish frontmatter followed by a Markdown body. The body
is the **prompt**; an optional `> **Объяснение**` callout (and everything after
it) is the **explanation** shown once the answer is checked or revealed.

### Common frontmatter fields

| Field | Required | Type | Rules |
|-------|----------|------|-------|
| `id` | yes | string | Unique across all exercises. Convention `<LEVEL>-EX-NN` (e.g. `A1-EX-01`). |
| `level` | yes | string | One of `A1 A2 B1 B2 C1 C2`. Must match the file's `<LEVEL>/` directory. |
| `theme` | yes | string | A theme id in `themes.json` whose level equals this exercise's level. |
| `card` | yes | string | An existing card id of the **same level** the exercise drills. |
| `type` | yes | string | One of the six types below. |

Type-specific value fields are JSON (a value beginning with `[` or `{` is parsed
as JSON; otherwise it is a quoted/plain scalar string):

| `type` | mode | fields |
|--------|------|--------|
| `multiple-choice` | auto | `options` (JSON array, ≥2 strings) + `answer` (the correct option, must be in `options`) |
| `fill-in-the-blank` | auto | `answer` (string) + optional `accept` (JSON array of accepted strings) |
| `matching` | auto | `pairs` (JSON array of `{"left":…,"right":…}`, ≥2) |
| `word-order` | auto | `tokens` (JSON array) + `answer` (target sentence) + optional `accept` (JSON array) |
| `picture-matching` | auto | `options` (JSON array of `{"image":…,"label":…}`, ≥2) — `image` names a bundled asset |
| `free-response` | self-assessed | `answer` (reference string) + optional `accept` (JSON array) |
| `listen-choose` | auto | `audio` (Spanish text spoken by the device voice, one line) + `options` (JSON array, ≥2) + `answer` (must be in `options`) |
| `dictation` | auto | `audio` (Spanish text spoken and typed back, one line, ≤ 120 characters) + optional `accept` (JSON array) |
| `speak` | auto with on-device recognition, else self-assessed | `answer` (Spanish target phrase, one line, ≤ 80 characters) + optional `accept` (JSON array) |

**Answer matching (auto types).** `fill-in-the-blank` and `word-order` compare
the user's input to the expected answer(s) under a **normalized** match:
case-folded, diacritics stripped (`á`→`a`, `ñ`→`n`), surrounding whitespace
trimmed, inner whitespace collapsed. `multiple-choice`/`matching`/`picture-matching`
compare selected identity. `free-response` is **self-assessed**: the reference is
revealed and the user grades themselves with the four grade buttons.

**Listening and speaking.** No audio files ship: `audio` is synthesised by the
device's Spanish voice. `dictation` is compared after lower-casing, trimming,
collapsing whitespace and stripping punctuation (incl. `¿ ¡`); an accent-only
difference is «почти» (Трудно). `speak` compares the recogniser's transcripts
with `answer`/`accept` ignoring diacritics; recognition runs on device only.

### Example (multiple-choice)

```markdown
---
id: A1-EX-01
level: A1
theme: a1-2
card: A1-07
type: multiple-choice
options: ["el", "la"]
answer: "la"
---
Какой артикль у слова **casa**?

> **Объяснение**
> Слова на **-a** обычно женского рода: *la casa*.
```

### Compiled shape

`compile.py` adds an `exercises` array to `content.json` next to `cards`. Each
entry carries the common fields plus the type-specific fields present, with the
body split into `prompt` and `explanation`:

```json
{ "id": "A1-EX-01", "level": "A1", "themeID": "a1-2", "card": "A1-07",
  "type": "multiple-choice", "prompt": "…markdown…", "explanation": "…markdown…",
  "options": ["el", "la"], "answer": "la" }
```

## Pipeline

See `tools/`:

- `migrate.py` — seed from the Obsidian vault into this format + generate `themes.json`
- `enrich.py` — expand a card body (identity-preserving; LLM integration point);
  `--recall <ID|LEVEL>` drafts recall prompts for review, `--set-recall <ID> "<text>"`
  writes one into the card's front matter
- `validate.py` — enforce every rule above (non-zero exit on failure)
- `compile.py` — validate, then compile to the app bundle (`content.json`)
- `test_pipeline.py` — pipeline unit tests

### `tenses.json` — registry of drillable tenses

A JSON array; each entry:

| Field | Meaning |
|---|---|
| `id` | unique kebab-case id (`presente`, `preterito-indefinido`, …); must be a tense the pipeline can generate |
| `es`, `ru` | Spanish and Russian names |
| `mood` | `indicativo`, `subjuntivo` or `condicional` |
| `level` | CEFR level of the teaching card |
| `card` | id of the existing card of that level that teaches the tense (unlocks it in the app) |
| `order` | display / unlock order |

### `verbs/<infinitive>.json` — one file per verb

| Field | Meaning |
|---|---|
| `infinitive` | must equal the file name (`levantarse` for reflexive verbs) |
| `rank` | unique positive integer, frequency order (lower = more frequent) |
| `ru` | Russian translation |
| `model` | `ar`, `er`, `ir` (regular paradigms generated) or `irregular` |
| `reflexive` | optional `true`: forms are drilled with the pronoun (`me levanto`) |
| `forms` | optional `{<tense-id>: [six forms]}` |

**Person order** in every form list: yo, tú, él/ella/usted, nosotros,
vosotros, ellos/ustedes.

**Generated vs overriding forms.** For `ar`/`er`/`ir` verbs
`tools/conjugate.py` generates all registered tenses (compound tenses as
haber + regular participle); a tense listed in `forms` replaces the generated
one entirely — use it for stem changes (`pensar`), orthographic changes
(`buscar → busqué`), irregular stems and participles (`volver → he vuelto`).
An `irregular` verb must list `forms` for every registered tense. Forms are
written without reflexive pronouns; the pipeline prefixes `me/te/se/nos/os/se`
for reflexive verbs. `tools/validate.py` checks the registry, ranks, models
and form counts; `tools/compile.py` writes the tenses and every verb's full
paradigms into the bundle under `conjugation`.

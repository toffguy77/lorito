# Design

## Context

- Упражнения запускаются только из `CardReaderView` через
  `CatalogModel.makeExerciseSession(forCard:)`. Это создаёт
  `ExerciseSessionModel`, которая для каждого ответа вызывает
  `ExercisePracticeService` → `GradingService.grade`.
- `GradingService` уже меняет `ReviewState` только на первой оценке элемента
  за учебный день; последующие оценки пишутся как `StudyEvent`. Правило
  остаётся в силе и для свободной практики (проверено).
- В `ExerciseSessionModel.init` аудиополитика (`AudioExercisePreferences`)
  уже отфильтровывает упражнения на слух и произношение; свободная практика
  получает это бесплатно.
- `ExerciseAttempt` (exercise id, card id, дата, `correct`, grade) уже хранится
  и синхронизируется. Этого хватает для «Слабых мест», новые поля не нужны.
- Монетизация: `ProFeature` пока содержит только `.examPath`,
  `Monetization.salesEnabled == false`; `ExamsModel.isPro` — образец гейта.
- Требования — в specs этого изменения; ниже только «как».

## Goals / Non-Goals

**Goals:**
- Чистый Domain-подбор упражнений для режимов, детерминированный в тестах.
- Один и тот же экран упражнений для ридера и свободной практики,
  отличающийся только политикой оценки.
- Без изменений SwiftData/CloudKit-схемы.

**Non-Goals:**
- Новая вкладка навигации.
- Упражнение вместо карточки в учебной сессии.
- Отдельное SRS-расписание для упражнений.
- Новые упражнения или изменения контент-пайплайна.

## Decisions

### D1. `PracticeSelector` — чистая функция в Domain
`Domain/Practice/PracticeSelector.swift`:
`select(mode:, exercises:, reviews:, attempts:, seed:) -> [Exercise]` и
`availability(scope:) -> (available: Int, total: Int)`.
- Допустимость: у карточки упражнения есть `ReviewState` со статусом ≠ `.new`.
- «Смешанная» и «по уровню»: сортировка по последней попытке (никогда не
  решённые первыми, затем самые давние), детерминированное перемешивание
  внутри одинаковых групп с инъектируемым seed, затем проход, разводящий
  соседние упражнения одной карточки; лимит 20.
- «Слабые места»: последняя попытка по `exerciseID` имеет `correct == false`;
  сортировка по дате промаха по убыванию; лимит 20.
- «По теме»: все допустимые упражнения в порядке `card.order`, затем id.
- Аудиофильтр остаётся в сессии (он зависит от устройства и времени), поэтому
  итоговая сессия может быть короче лимита. Счётчик «доступно X из Y»
  считается без аудиофильтра, чтобы совпадать с содержимым каталога.

Альтернатива: собирать выборку в `CatalogModel` / `TodayModel`. Отклонено:
логика нужна в двух моделях и должна тестироваться через `swift test`
без UI.

### D2. Политика оценки как параметр сессии
`enum PracticeGrading { case reader, free }` передаётся в
`ExerciseSessionModel` (по умолчанию `.reader`, поэтому вызов из ридера не
меняется). `ExercisePracticeService` получает метод проверки с этой политикой:
- `.reader`: как сейчас;
- `.free`: проходной результат → `appendAttempt(correct: true)`, без
  `GradingService`; провал → существующий путь с `.again`.
`recordAttemptOnly` сейчас жёстко пишет `correct: false`; добавляется
параметр `correct`. Ветка `speak` («никогда не роняет карточку») остаётся
первой проверкой, поэтому в `.free` `speak` вообще не трогает расписание.

Альтернатива: отдельная сессия-модель для свободной практики. Отклонено:
дублирует 9 типов упражнений и аудиологику.

Следствие: верные ответы в свободной практике не создают `StudyEvent`,
поэтому они не продлевают серию и не попадают в «изучено сегодня». Это
сделано намеренно: серия и счётчики дня остаются про учебный план. Ошибка
создаёт событие, как и любая оценка карточки.

### D3. Pro-гейт через `ProFeature.practice`
Добавить `ProFeature.practice`; `EntitlementResolver` при наличии покупки
возвращает `[.examPath, .practice]`. Состояние доступа считается так же,
как `ExamsModel.isPro`: `!Monetization.salesEnabled || isEntitled(.practice)`.
Модель практики получает `purchases` так же, как `ExamsModel`. Новый
`PaywallEntry.practice`, а в списке функций пейвола появляется строка о
свободной практике. При выключенных продажах замки не показываются
(требование «Sales switch»).

### D4. UI
- **Сегодня**: `practiceEntry` между `examEntry` и `conjugationEntry`, в том же
  стиле строк, с подписью «Упражнения по изученным карточкам». Открывает
  лист `PracticeHubView`: две строки режимов с «доступно X из Y», пустые
  состояния и сноска «По теме и уровню — в Каталоге».
- **Каталог**: в `themeCards(_:)` — `PrimaryButton("Практика по теме")` над
  списком карточек; в списке уровня (compact и regular, рядом с `examsRow`) —
  строка «Практика по уровню A2». Обе показывают «доступно X из Y».
- Сессия: существующий `ExerciseSessionView` в фокус-режиме;
  `SessionCompleteView` получает подзаголовок «Верно X из N».
- Идентификаторы доступности: `today.practice`, `practice.mode.mixed`,
  `practice.mode.weak`, `catalog.practice.theme`, `catalog.practice.level`.
- Пустое состояние — алерт «Пока нечего тренировать» с причиной
  (общий компонент `PracticeEntryButton` держит сессию, алерт и пейвол для
  любой точки входа).

### D5. Аналитика
`AnalyticsEvent.practiceStarted(mode: PracticeModeName, count: Int)`, где
`PracticeModeName` — закрытый enum `mixed | weak | theme | level`. Без
идентификаторов темы и уровня, как требует таксономия.

## Risks / Trade-offs

- [Ошибка в свободной практике после сегодняшней учебной сессии не меняет
  расписание (правило первой оценки за день)] → Задокументировано в
  сценарии спеки. Промах всё равно попадает в «Слабые места», так что сигнал
  не теряется.
- [Аудиофильтр сокращает сессию ниже показанного счётчика] → Счётчик
  описывает доступность контента, а не длину сессии. Если после фильтра
  ничего не осталось, показать пустое состояние с причиной (нет голоса или
  аудио выключено).
- [Чтение всех `allAttempts()` и `allEvents()` на каждый подсчёт] → Объём
  небольшой (сотни–тысячи записей); подсчёт делается при открытии экрана и
  `refresh()`, а не в `body`.
- [Pro-гейт на функции, которая сейчас бесплатна по смыслу] → Продажи
  выключены, поведение для пользователей не меняется. Включение продаж —
  отдельное решение владельца.

## Migration Plan

Миграции данных нет: схема не меняется. Откат — удалить точки входа; попытки
свободной практики остаются обычными `ExerciseAttempt`.

## ADDED Requirements

### Requirement: Grammar-first positioning
The Russian App Store product page SHALL position Lorito as Spanish grammar explained in Russian from A1 to C2. The name or subtitle SHALL contain the word «грамматика» or an equivalent grammar term, and the first sentence of the description and the promotional text SHALL state that rules are explained in Russian.

#### Scenario: First screen states the differentiator
- **WHEN** a user views the product page without expanding the description
- **THEN** the name, subtitle and promotional text together say that this is Spanish grammar explained in Russian

### Requirement: Metadata within Apple limits
Metadata files SHALL respect Apple's limits: name 2–30 characters, subtitle at most 30 characters, promotional text at most 170 characters, description at most 4000 characters, keywords at most 100 characters with every keyword longer than two characters and none repeating a word from the app name.

#### Scenario: Over-limit subtitle rejected locally
- **WHEN** the subtitle file contains 31 characters
- **THEN** the metadata lint fails before upload

### Requirement: Metadata describes shipped features only
Keywords, description and screenshots SHALL mention only features available in the build being submitted. Exam-related terms such as DELE and CCSE SHALL be added only in the release that ships exam preparation.

#### Scenario: Exam terms before exam feature
- **WHEN** a release without exam preparation is prepared
- **THEN** its keywords and description do not contain DELE or CCSE

### Requirement: Description content from the repository
Counts quoted in the description (cards, exercises, levels) SHALL match the content bundle of the submitted build, and the description SHALL state that the app works offline, needs no account and shows no ads.

#### Scenario: Card count matches content
- **WHEN** the description says the app has 159 rule cards
- **THEN** the compiled content bundle of that build contains 159 cards

### Requirement: Benefit-led screenshot set
Each device class (iPhone and iPad) SHALL have a screenshot set of six scenes generated by UI tests — Today plan, recall-first card front, revealed card with common mistakes, exercise, progress, catalog — each with a one-line Russian benefit headline.

#### Scenario: Screenshots regenerated
- **WHEN** the screenshot UI tests run for iPhone and iPad
- **THEN** six framed screenshots with headlines are produced per device class

### Requirement: Automated metadata lint
A standard-library Python script SHALL validate all metadata files against the limits and keyword rules, exit non-zero on any violation, report UTF-8 byte length of keywords as a warning, and run in CI before upload.

#### Scenario: Duplicate keyword
- **WHEN** the keywords file lists «глаголы» twice
- **THEN** the lint exits non-zero naming the duplicate

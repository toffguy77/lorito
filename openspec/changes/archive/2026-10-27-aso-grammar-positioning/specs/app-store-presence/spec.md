## ADDED Requirements

### Requirement: Grammar-first positioning
The Russian App Store product page SHALL use the name «Lorito: испанский язык» and the subtitle «Грамматика по-русски, A1–C2», and the first sentence of the description and the promotional text SHALL state that Spanish grammar is explained in Russian from A1 to C2.

#### Scenario: First screen states the differentiator
- **WHEN** a user views the Russian product page without expanding the description
- **THEN** the name, subtitle and promotional text together say that this is Spanish explained in Russian with grammar from A1 to C2

### Requirement: Metadata within limits
Every localization's metadata SHALL respect: name 2–30 characters, subtitle at most 30 characters, promotional text at most 170 characters, description at most 4000 characters, keywords at most 100 characters, every keyword longer than two characters, no duplicate keyword, and no keyword repeating a word of that localization's name or subtitle.

#### Scenario: Over-limit subtitle rejected locally
- **WHEN** a subtitle file contains 31 characters
- **THEN** the metadata lint fails before upload

#### Scenario: Short keyword rejected
- **WHEN** the keywords contain «B1»
- **THEN** the metadata lint fails naming that keyword

### Requirement: Metadata describes shipped features only
Keywords, description and screenshots SHALL mention only features available in the submitted build. Exam terms (DELE, CCSE, экзамен, гражданство) SHALL be added only in the release that ships exam preparation.

#### Scenario: Exam terms before exam feature
- **WHEN** a release without exam preparation is prepared
- **THEN** its keywords and description contain none of DELE, CCSE, экзамен, гражданство

### Requirement: Description content from the repository
Counts quoted in the description (cards, exercises, levels) SHALL match the content bundle of the submitted build, and the description SHALL state that the core works offline, needs no account and shows no ads.

#### Scenario: Card count matches content
- **WHEN** the description says the app has 159 rule cards
- **THEN** the compiled content bundle of that build contains 159 cards

### Requirement: In-app purchase disclosure
From the release in which `lorito-pro` ships, the description of every localization SHALL state which content is free and which requires a purchase.

#### Scenario: Pro release
- **WHEN** the first build containing Lorito Pro is submitted
- **THEN** each description names the free core and the paid features

### Requirement: Russian metadata in diaspora storefront localizations
The app SHALL provide es-ES and es-MX localizations whose metadata is written in Russian for Russian speakers learning Spanish, keep the same name as the Russian localization, and state in the description's first line who the app is for. This SHALL be tracked as an experiment by impressions and installs in Spain, Mexico and Argentina.

#### Scenario: Visible in Spain
- **WHEN** a user in the Spain storefront searches «испанский язык»
- **THEN** Lorito's es-ES localization with Russian metadata can match the query

### Requirement: Benefit-led screenshot set
Each device class (iPhone and iPad) SHALL have six screenshots generated by UI tests from a seeded demo store — Today plan, recall-first card front, revealed card with common mistakes, exercise, progress, catalog — each with a one-line Russian benefit headline.

#### Scenario: Screenshots regenerated
- **WHEN** the screenshot UI tests run with the demo store for iPhone and iPad
- **THEN** six framed screenshots with headlines and non-empty data are produced per device class

### Requirement: Automated metadata lint
A standard-library Python script SHALL validate all metadata files of all localizations against the limits and keyword rules, exit non-zero on any violation, and run in CI before upload.

#### Scenario: Duplicate keyword
- **WHEN** a keywords file lists «глаголы» twice
- **THEN** the lint exits non-zero naming the duplicate

### Requirement: Upload through App Store Connect API
Metadata and screenshots SHALL be uploaded with the existing fastlane lane using the App Store Connect API key, and the upload result SHALL be checked so that any field App Store Connect rejects fails the lane.

#### Scenario: Rejected field
- **WHEN** App Store Connect rejects a keyword field during upload
- **THEN** the lane fails and reports the field and localization
